# Исследовательские и технические заметки

Дата: **2026-09-10**. Этот файл фиксирует существенные находки и решения; первичные ссылки и границы подтверждения — в [SOURCES.md](SOURCES.md), [российском исследовании](docs/RUSSIAN_SOURCES_RESEARCH.md) и [международном исследовании](docs/INTERNATIONAL_SOURCES_RESEARCH.md).

## 1. Подход к исследованию

Проверка официальных источников предшествовала выбору адаптеров. Для российских перечней сверялись даты документов, структура выгрузок и ответы публичных интерфейсов; для международных баз — документация API и доступные реальные ответы. Условия доступа, подтверждённые запросами, отделены от возможностей, описанных только в документации. Выбор реализации опирается на эти наблюдения и проверку доменных алгоритмов.

## 2. Ошибка в математическом условии

Ожидаемое `h=5` для `[10,8,5,4,3,1]` противоречит определению. Реализован и проверен `h=4`. Для примера `h=5` подходит `[10,8,5,5,5,1]`. Программа не подстраивает алгоритм под неверный пример. Это отдельно отмечено в README, отчёте и шпаргалке.

## 3. Актуальность российских данных

Официальный сайт ВАК использует JavaScript. Поисковый индекс указывал июньскую версию, но живой JSON публичного интерфейса и заголовок скачанного PDF показали **14.08.2026**. Массив вложений содержит исторические документы; актуальная ссылка обнаружена в содержимом текущего объявления, а не выбором первого файла. В проекте не рекламируется неофициальный frontend endpoint как стабильный API журналов.

В PDF 1 277 страниц и 3 229 номеров. Некоторые прошлые названия содержат исторические ISSN; автоматический поиск всех похожих чисел по странице создал бы ложные связи. Поэтому используется координатное выделение колонок. Названия, специальности и даты продолжаются через строки/страницы; исходные фрагменты и номера страниц сохранены. 3 202 записи прошли проверку, 27 помещены в карантин. У десяти отсутствует ISSN; у семнадцати контрольная цифра хотя бы одного ISSN невалидна. Точная расшифровка — в исходном аудите.

«Белый список» имеет работающий открытый API и официальный JSON. Фраза старого FAQ о планируемом API уступает по доказательной силе отдельной документации и успешному запросу. API и JSON используют разные имена полей (`issn`/`issns`, camelCase/snake_case). Схема документации отстаёт от примера в части 2026 года; парсер принимает `level_YYYY` с проверкой диапазона значений.

Полный JSON содержит 31 576 объектов, в том числе 515 с датой исключения. Из этого нельзя получить число действующих журналов простым подсчётом всех импортированных строк. Поля уровней могут относиться к 2023, 2025 или 2026; null сохраняется. Программа не называет предыдущий уровень «квартилем 2026». Внешние метки Scopus/WoS в экспорте являются утверждениями РЦНИ с отдельными датами обновления.

## 4. eLIBRARY и точность терминологии

Нельзя писать «API eLIBRARY не существует»: он существует, но текущие условия конкретного доступа проекту не подтверждены. Официальная страница встретила блокировку IP. Не выполнялись CAPTCHA, смена идентичности клиента, поиск чужих учётных данных или обход подписки. Решение — импорт разрешённых данных в документированную нейтральную схему.

Регламент Ядра РИНЦ от 18.02.2026 расширяет понимание корпуса за пределы упрощённого WoS/Scopus/RSCI union. В отчёте различаются РИНЦ, eLIBRARY, RSCI и Ядро РИНЦ. Категории ВАК, уровни ЕГПНИ и международные квартили хранятся как самостоятельные классификации.

## 5. Изменения международных API в 2026 году

OpenAlex в начале года объявлял ключи обязательными, но актуальная документация августа разрешает ограниченное анонимное использование. Живой запрос подтвердил доступ без ключа из этой среды. Это не гарантия неограниченного доступа. Ключ передаётся через bearer header; максимальный `per_page=100`, а не устаревшие 200.

Crossref в июле 2026 уточнил разные лимиты списков и одиночных записей. В приложении запросы последовательны, базовый интервал 1.05 секунды, заголовки и 429 учитываются. Отсутствующий `mailto` оставляет public pool; подставной контакт не создаётся.

ORCID публично вернул запись `0000-0001-7175-3497` без токена. В ней обнаружены 45 связей DOI с отношением `self`; `part-of` не используется как DOI самой работы. Crossref ORCID-фильтр проверен отдельно. ORCID assertions не превращаются в citation metrics.

Elsevier API требует key и соответствующих прав; Insttoken не выводится из API key. Citation Overview имеет отдельный допуск. Реализован небольшой адаптер, но авторизованный живой Scopus не проверен. Сырые метрики Serial Title не превращаются в вымышленные квартильные записи.

## 6. Выбор реализации

Целевая версия — Python 3.12 или новее; проверка выполнена на Python 3.12.14. Зависимости ограничены HTTP-клиентом, XLSX и PDF-парсером; ORM, сервер и внешняя база не потребовались. SQLite и стандартные dataclasses достаточны для небольшого воспроизводимого прототипа.

Авторский поиск возвращает кандидатов. Имя не является ключом сущности. Корпус работ определяется выбранным устойчивым ID, после чего другие источники обогащают его DOI. Fuzzy matching создаёт объяснение для проверки. Высокий балл без общего идентификатора не вызывает автоматическое объединение.

Для отсутствующего DOI альтернативные языки названия, перестановка авторов и год online-first рассматриваются консервативно. При общем DOI альтернативы сохраняются. В метриках никогда не суммируются разные базы; h по sample обозначается именно как sample. Невалидный счётчик и отсутствие наблюдений дают `insufficient_data`, а не искусственный ноль.

## 7. Найденные при проверке ошибки и исправления

- Контракт нормализаторов возвращал `None` для невалидного ID; адаптеры первоначально ожидали исключение. Валидация исправлена, ошибочные ISSN помещаются в карантин до обращения к хранилищу.
- Первоначальное обогащение мутировало список `Batch.items`, увеличивая счётчик полученных работ с 3 до 6 при добавлении второго источника. Теперь сервис копирует список; регрессионный тест проверяет `retrieved=3` независимо от числа источников.
- Обновление публикации в SQLite первоначально могло стирать предыдущие наблюдения. Теперь сохраняются снимки и provenance, а конфликт DOI при одном ID отклоняется транзакционно.
- Сравнение timestamp строками неверно для разных UTC-смещений. Времена приводятся к одному часовому поясу; конфликт значений на одном моменте фиксируется явно.
- Валидный JSON неожиданной формы мог вызвать `AttributeError` и прервать все источники. Ошибка разбора изолируется; следующий провайдер продолжает работу.
- Первоначальная загрузка 31 тысячи журналов делала commit для каждой строки. Она была прервана, затем реализованы пакетные durable-транзакции по 500 записей и row savepoints. Программа не отключает fsync/проверку сертификатов ради ускорения.

## 8. Воспроизводимость и границы доказательства

Исходные российские файлы имеют manifests с URL, датой и SHA-256. Быстрое восстановление ВАК проверяет не только hash производного JSON, но и его связь с исходным PDF и аудитом отклонённых строк. Новый download получает уникальное имя и не подменяет исследовательский снимок. Смена источников требует повторной проверки.

Сохранённые реальные ответы и synthetic fixtures находятся в разных папках. Форматы CSV/XLSX предназначены для просмотра, JSON является полным экспортом; Excel ограничивает длину ячейки. Ключи не должны включаться в raw fixtures. Данные полного текста, закрытые профили и личная переписка не собирались.

Фактическая доступность источника на одном IP в один день не доказывает доступности навсегда. Официальная документация не доказывает наличия entitlement у пользователя. Успешные тесты на fixtures не заменяют живой запрос. Разделение этих уровней доказательства выдержано в [VALIDATION.md](VALIDATION.md).
